*sshdev.txt*	Edit remote projects with your local Neovim config, over SSH.

Author: mistgc and sshdev.nvim contributors     MIT licensed    *sshdev*

==============================================================================
INTRODUCTION						*sshdev-intro*

A local Neovim UI is attached to a remote `nvim --headless --listen`
server through an SSH port forward: >

	local UI / --remote-ui client  <->  ssh -N -L  <->  remote nvim --listen

Terminology ~
							*sshdev-workspace*
	workspace	the remote PROJECT DIRECTORY the server runs in,
			e.g. "~/src/app".

	profile		the remote state directory for one
			(client machine, workspace) pair:
							*sshdev-profile*
			  <remote_root>/--<local-hostname>--<workspace-path>--/
			The key uses the LOCAL hostname, so several client
			machines sharing one remote account stay isolated
			(config, plugins, data, session, logs).

What sshdev.nvim does for a workspace:

1. Uploads |stdpath()|'s "config" to `<profile>/nvim-config/` with scp,
   respecting `excludes`. Skipped when the local config fingerprint
   matches the remote `.synced` marker.
2. Ensures a Neovim release matching your local version exists under
   `~/.sshdev.nvim/_bin/<version>-<asset>/` (downloading through `proxy` /
   `download_mirror` if configured).
3. Runs the remote nvim headless once so your plugin manager's bootstrap
   installs the plugins declared in your config.
4. Starts a detached server in the workspace, forwards it, and attaches.
5. Persists the session: the server writes `<profile>/session.vim` when it
   exits and restores it on the next start. There is no quit hijacking --
   |:q| behaves normally.

Requirements: Neovim >= 0.12 locally (:connect was added in 0.12), ssh/scp (OpenSSH >= 7.6), POSIX
remote (Linux/macOS) with tar and curl. Key-based authentication is
strongly recommended.

==============================================================================
COMMANDS						*sshdev-commands*

*:SSHdevConnect*
:SSHdevConnect[!] [{dest}] [{workspace}]	Connect (bootstrap + attach).
	Without arguments, opens the connection picker (telescope when
	installed, |vim.ui.select()| otherwise) with the remembered
	connections plus a "new connection" entry.
	{dest} is a destination "[user@]host[:port]" or a key from
	`remotes`; defaults to `host`. {workspace} is the remote project
	directory (default: `workspace`, then the remote $HOME).
	With !, a running server is stopped and config/plugins are
	re-synced before starting a fresh one.

*:SSHdevAttach*
:SSHdevAttach [{dest}] [{workspace}]	Attach to a RUNNING server (no
	bootstrap). Fails if no server is running for the profile.

*:SSHdevInstall*
:SSHdevInstall [{dest}] [{workspace}]	Bootstrap only: binary, config,
	headless plugin install. Does not start or attach.

*:SSHdevSync*
:SSHdevSync [{dest}] [{workspace}]	Re-upload config + session helper.
	Use :SSHdevConnect! to restart the server with the new config.

*:SSHdevStop*
:SSHdevStop			Stop the remote server (SIGTERM, so it saves
	session.vim) and kill the local tunnel.

*:SSHdevStatus*
:SSHdevStatus			Report session, workspace, profile,
	tunnel, remote server and saved-session state.

*:SSHdevHistory*
:SSHdevHistory			Open the remembered-connection picker.

*:SSHdevLog*
:SSHdevLog			Open the sshdev log buffer.

Telescope (optional): >

	:Telescope sshdev connections
	require('telescope').extensions.sshdev.connections()
<
	`<C-d>` in the picker forgets the highlighted connection.

==============================================================================
SESSION PERSISTENCE					*sshdev-session*

The remote server saves its Neovim session to `<profile>/session.vim`:

	* on VimLeavePre (:q, :wq, :cquit, SIGTERM from :SSHdevStop, ...)
	* on FocusLost / VimSuspend (best-effort snapshot)

and restores it on the next start (VimEnter), so reconnecting brings back
buffers, windows and layout. |:q| therefore behaves normally -- the server
exits and the session is preserved for the next connection.

Configure with `session` (save/restore on/off) and `restore_session`
(start clean while still saving). SIGKILL cannot be handled.

==============================================================================
ATTACHING						*sshdev-attach*

Since Nvim 0.12, running `nvim` starts a builtin UI client process plus an
embedded server, and that UI client implements the "connect" UI event. So
|:connect| re-attaches the terminal UI in place: >

	:connect 127.0.0.1:<port>

The address must be a bare "host:port" (or the |ssh://| builtin remote-ssh
form). A "tcp://host:port" URI is NOT a valid nvim server address: the UI
detaches first, the attach fails, and the process ends -- which makes
|:connect| look unsupported. (:connect was added in 0.12; 0.11 only has
|:detach|.)

`attach` selects the strategy:

	"auto"      (default) |:connect| when the command exists (>= 0.12);
	            headless -> "command"
	"connect"   always |:connect| "127.0.0.1:<port>"
	"terminal"  open a terminal tab running a separate UI client:
	            nvim --server 127.0.0.1:<port> --remote-ui
	            (keeps the local nvim alive while working remotely)
	"command"   do not attach; just report the command to run

REMOTE LAYOUT						*sshdev-remote-layout*

    ~/.sshdev.nvim/_bin/<version>-<asset>/    nvim releases (shared)
    ~/.sshdev.nvim/--<local-host>-<ws-path>--/    one profile
        nvim-config/                          uploaded config
        data/ state/ cache/                   XDG data/state/cache
        session.lua                           session helper
        session.vim                           saved session
        .synced                               config fingerprint marker
        server.pid server.addr server.log

The server runs with `NVIM_APPNAME=nvim-config`, with the XDG dirs
pointing into the profile, so state never collides with the remote user's
own nvim or with other profiles.

The server is located through `<profile>/server.pid`; if that file is lost
the scripts fall back to matching the unique command line
("<profile>/session.lua"), so a lost pid file never starts a second server.

SETUP							*sshdev-setup* *sshdev-setup()*

Setup with defaults (all keys optional): >

	require('sshdev').setup({
	  host = 'me@myhost',          -- default destination
	  remotes = { work = 'me@work.example.com:2222' },
	  workspace = '~/src/app',     -- default remote project directory
	  profile = nil,               -- force the profile dir name
	  session = true,              -- save <profile>/session.vim on exit
	  restore_session = true,      -- restore it on start
	  ssh_bin = 'ssh', scp_bin = 'scp',
	  ssh_args = { '-i', '~/.ssh/id_ed25519' },
	  remote_root = '~/.sshdev.nvim',
	  nvim_version = 'auto',       -- "auto" | "v0.12.6" | "nightly" | "stable"
	  proxy = 'http://127.0.0.1:7890',
	  download_mirror = 'https://github.com/neovim/neovim/releases/download',
	  install_commands = { 'Lazy! restore' },
	  excludes = { '.git', '.github' },
	  attach = 'auto',             -- "auto" | "terminal" | "connect" | "command"
	  history = true,              -- remember connections for the picker
	  history_limit = 50,
	  timeouts = { ssh = 60, download = 600, install = 900, attach = 30 },
	})

host / remotes ~
	`host` is used when :SSHdevConnect is called without arguments.
	`remotes` maps names to destinations; its keys complete for
	:SSHdevConnect.

workspace ~
	The remote project directory. Absolute or "~/...". The remote nvim
	server's |current-directory| is set to it and it names the profile.

profile ~
	Force the profile directory name. Default:
	"--<local-hostname>--<workspace-path>--". Both clients and workspaces
	stay isolated; the picker remembers them for you.

nvim_version ~
	"auto" (default) installs the release matching your local nvim.
	Dev builds fall back to "nightly" with a warning.

proxy / download_mirror ~
	Both apply to the nvim download ON THE REMOTE host.

install_commands ~
	Extra ex-commands for the headless install run (after your config is
	sourced), e.g. { "Lazy! restore" }.

excludes ~
	Globs matched against paths relative to your config root.

session / restore_session ~
	See |sshdev-session|.

attach ~
	See |sshdev-attach|.

history / history_limit ~
	Remembered connections for the :SSHdevConnect picker, stored in
	|stdpath()|'s "data"/sshdev/history.json. Entries keep the full
	destination including the ssh port.

TROUBLESHOOTING					*sshdev-troubleshooting*

:SSHdevLog shows scp/ssh output, plugin install output and tunnel
messages; the remote server log is `<profile>/server.log`.

- "ssh connection failed" -- check key auth works: `ssh <dest> true`.
- Slow first connect -- the nvim release and all plugins are downloaded
  once per remote; subsequent connects reuse them.
- Session not restored -- check that the server exited normally (SIGKILL
  cannot save) and that `restore_session` is true.
- Port collisions -- local/remote ports are deterministic per profile;
  start retries with incremented remote ports automatically.
- Remote plugin install skipped unexpectedly -- the config fingerprint is
  unchanged; use :SSHdevConnect! to force a re-sync.
